主要request flow

認可の要点: SystemAdmin → user explicit None → user grant → active group grants の最大値 → grantなし None。一覧だけでなく詳細・起動・管理操作でも再判定します。

Build → release → rollback

会社固有値はGitHub Environmentから注入し、リポジトリに保存しません。

失敗時: 配備前のtimestamp backupがあれば自動restoreして再起動。初回配備でbackupがなければIIS site/app poolを停止し、障害状態の公開を避けます。
実サーバー名、DB名、URL、credential、certificate、会社名は構成ファイルに固定しません。必要値は COMPANY_ENVIRONMENT_INPUTS.md と GitHub Environment で引き渡します。

Governance

本番判定

branch protection、Environment approver、retention、DR、OSS reviewが必要。

推奨する次の5アクション

  1. 会社環境入力票へownerと承認者を割り当てる。
  2. branch protectionとGitHub Environmentsを設定する。
  3. 会社標準SQL Serverでmigration/restore rehearsalを行う。
  4. IIS stagingでsmoke/rollbackを通す。
  5. SSRF、secret、PII、audit retentionのsecurity reviewを行う。
